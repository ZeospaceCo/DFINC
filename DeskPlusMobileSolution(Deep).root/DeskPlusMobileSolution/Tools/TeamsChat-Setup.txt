DeskPlusMobile 메신저 알람 Teams 1:1 채팅 연동 (.NET Framework 4.8 / VS2022)

적용 범위
  결재, 게시판, 일정, 업무, 협업, 커뮤니티, SNS, 자원관리, MDM 등 모든 메신저 알람을 Teams에도 전송합니다.
  각 업무의 기존 알람 설정과 수신자의 메신저 알람 설정을 따릅니다.
  공통 Messenger/BLL/Alarm.cs에서 AlarmType=1인 모든 알람을 업무 구분(KindSubject)과 관계없이 처리합니다.
  메일, SMS 및 모바일 푸시는 기존 방식으로 처리합니다.
  Teams 발송 실패는 기록하고 기존 알람 저장 결과를 그대로 반환합니다.

설정
  1. DeskPlusMobile/WebAppSettings.config.example을 WebAppSettings.config로 복사합니다.
     Web.config의 appSettings file="WebAppSettings.config"에서 읽습니다.
  2. DeskPlusEIP/WebAppSettings.config와 아래 설정을 동일하게 지정합니다.
     TeamsTenantId, TeamsClientId, TeamsSenderUserPrincipalName, TeamsChatTokenPath
     TeamsChatEnabled=true이면 모든 메신저 알람을 Teams에도 전송합니다.
     설정이 없거나 false이면 Teams 발송을 비활성화합니다.
  3. 실제 IIS 서버에서 발신 계정의 최초 로그인이 필요합니다.
     같은 서버의 웹에서 이미 연결했다면 동일한 보호 토큰 파일을 함께 사용합니다.
     모바일 IIS 실행 계정에도 토큰 디렉터리 수정 권한이 필요합니다.
     토큰 파일은 웹/소스 폴더 밖에 두며 Git에 저장하지 않습니다.

최초 연결
  저장소 최상위 디렉터리에서 관리자 Windows PowerShell 5.1을 실행합니다.

  powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\DeskPlusSolution.root\DeskPlusSolution\Tools\Connect-TeamsChat.ps1 -ConfigPath '.\DeskPlusMobileSolution(Deep).root\DeskPlusMobileSolution\DeskPlusMobile\WebAppSettings.config' -IisIdentity 'IIS APPPOOL\DeskPlusEIP'

  실제 앱 풀 또는 서비스 실행 계정에 맞게 IisIdentity를 지정합니다.
  웹과 모바일의 앱 풀이 다르면 두 실행 계정 모두 토큰 디렉터리 수정 권한이 필요합니다.
  Microsoft 로그인과 MFA는 발신 계정 사용자가 직접 완료합니다.
  연결 스크립트는 테스트 채팅을 보내지 않으며, 연결 후 TeamsChatEnabled를 true로 설정합니다.
  권한 및 Entra 앱 설정은 웹 솔루션 Tools/TeamsChat-Setup.txt를 참고합니다.

발송 내용
  회사/수신자 ID로 조회한 DB 메일 주소를 사용합니다. Mail이 없으면 MailID@MailDomain을 사용합니다.
  제목, 본문, 알림 일시와 각 업무의 기존 문서 링크를 전송합니다.
  웹과 동일한 Microsoft Graph 위임 로그인, 1:1 채팅 재사용 및 중복 방지를 위한 발송 1회 정책을 사용합니다.
  기존 웹 구현을 모바일 네임스페이스와 예외 로그에 맞게 적용했습니다.
