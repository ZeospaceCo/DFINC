종료 전 미완료자 Teams 재알람 스케줄 설정

1. 처리 기준
   - 회사는 CompanyID = 1로 고정합니다.
   - 한국 시간(KST)의 오늘 날짜가 EndDate - AlarmDay인 교육을 대상으로 합니다.
   - 미알람(AlarmDay = 0)은 제외합니다.
   - 미완료 재직 대상자만 발송하며, 동일한 교육·대상자·알람 기준의 발송 이력으로 중복 실행을 방지합니다.
   - 기존 메신저 큐 접수 성공과 새 Teams 발송 성공 이력을 확인하여 같은 알람의 재발송을 방지합니다.
   - 실패 이력이 있는 대상자는 해당 교육 종료일 이내라면 다음 날 실행에서도 재시도합니다.
   - 알람 발송 처리 후 CompanyID = 1의 오래된 DP_EDU_AlarmHistory 이력을 자동 정리합니다.
     별도 정리 스케줄은 필요 없으며 기존 Alarm.aspx 호출에서 함께 실행합니다.
   - 교육 종료일이 한국 시간의 오늘 - 7일보다 이전이고, 가장 최근 처리일 및 큐 접수일도
     오늘 - 7일보다 이전인 이력만 삭제합니다. 최근 7일 이내 또는 경계일의 이력은 보존합니다.
   - 예: 2026-10-15 실행 시 종료일이 2026-10-07인 교육의 이력은 정리 대상이며,
     종료일이 2026-10-08인 교육의 이력은 보존합니다. 단, 최근 처리·큐 접수 이력은 위 보존 기준을 우선 적용합니다.
   - 삭제된 교육의 이력도 가장 최근 처리·큐 접수일을 기준으로 7일 이내 또는 경계일의 이력은 보존한 뒤 정리합니다.
   - Teams 발송 이력도 교육 종료일과 발송 기록을 기준으로 같은 보존 기간을 적용합니다.
   - 이 페이지는 진행상태 갱신 프로시저의 실행을 대신하지 않습니다.

2. 배포 파일
   - /DeskPlusEIP/Education/Scheduler/Alarm.aspx
   - 교육 BE / DAL / BLL / Web 및 Common.BLL 빌드 DLL을 함께 배포합니다.
   - 배포 전에 사이트의 SQLConnSolution DB에 dbo.DP_EDU_AlarmTeamsDelivery 테이블이 생성되어 있는지 확인합니다.
     웹 실행 계정에는 dbo.DP_EDU_AlarmTeamsDelivery 조회·추가·수정·삭제 권한과 교육 대상 테이블/뷰 조회 권한이 필요합니다.
   - 기존 dbo.DP_EDU_Alarm_SelTargets, DP_EDU_Alarm_RecordFailure, DP_EDU_Alarm_CleanupHistory 프로시저를 계속 사용합니다.
   - IIS의 기존 Teams 채팅 설정과 발신 계정 연결을 사용합니다. 자세한 설정은 Tools/TeamsChat-Setup.txt를 참고합니다.
   - 배포 중 기존 메신저 큐 코드와 Teams 코드가 동시에 스케줄 요청을 처리하지 않도록 작업을 잠시 중지합니다.
   - Scheduler/InvokeEducationAlarm.ps1은 웹 루트 밖의 운영 스케줄 폴더로 복사하여 사용합니다.
   - 외부 호출 허용을 적용할 때 변경된 교육 Web DLL을 배포하고, 운영 스케줄 폴더의 스크립트도 새 파일로 교체합니다.

3. 페이지 호출 방법 및 주의사항
   - 이 페이지만 로그인 없이 접근할 수 있고, 다른 교육 페이지의 인증은 유지됩니다.
   - EducationSchedulerKey 설정, 키 파일 및 키 요청 헤더는 사용하지 않습니다.
   - 아래 주소를 브라우저에서 열거나 스케줄 스크립트로 POST 호출하면 알람을 발송합니다.
     http://ep.dfinc.co.kr/DeskPlusEIP/Education/Scheduler/Alarm.aspx
   - GET 및 POST 요청만 허용합니다. 두 방식 모두 실제 Teams 채팅 발송과 오래된 알람 이력 정리를 처리합니다.
     브라우저로 주소를 여는 것도 실제 실행이므로 연결 확인만을 위한 용도로 호출하지 마십시오.
   - 호출 위치 및 클라이언트 IP를 제한하지 않으므로 외부에서도 호출할 수 있습니다.
   - 로그인·호출키·IP 제한이 없는 공개 실행 페이지입니다. URL에 접근할 수 있는 누구나 GET/POST로
     실제 Teams 채팅 발송 및 이력 정리를 실행할 수 있으므로 공개 노출 위험을 고려하여 운영하십시오.
   - GET/POST 이외의 요청 방식은 HTTP 405로 거부합니다.
   - 처리 완료: HTTP 200와 JSON 건수. 일부 실패/서버 오류: HTTP 500.
   - 스크립트의 기본 주소는 위 운영 도메인입니다. URL 형식과 DNS 해석 결과가 있는지만 검사하며,
     도메인이 현재 실행 서버의 IP로 해석되는지 확인하지 않습니다. NAT 또는 외부 IP도 허용합니다.
   - IIS 바인딩, 방화벽, DNS 및 네트워크 경로가 해당 교육 사이트로 정상 연결되어야 합니다.
     이 스크립트를 사용하기 위해 별도의 127.0.0.1 바인딩을 추가할 필요는 없습니다.
   - 리다이렉트와 프록시는 사용하지 않으며 HTTPS 인증서 검증을 끄지 않습니다.

4. Windows 작업 스케줄러 등록 (아래 설정은 예시이며 자동 등록하지 않음)
   - IIS 서버 또는 위 주소에 네트워크로 접근할 수 있는 다른 Windows 컴퓨터에서 실행할 수 있습니다.
   - 프로그램: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
   - 실제 발송 전에 아래 인수로 호출 주소를 먼저 점검할 수 있습니다.
     -NoProfile -NonInteractive -File "D:\DeskPlusSolution\DeskPlusScheduler\InvokeEducationAlarm.ps1" -Url "http://ep.dfinc.co.kr/DeskPlusEIP/Education/Scheduler/Alarm.aspx" -ValidateOnly
   - -ValidateOnly는 URL 형식 및 DNS 해석만 검사합니다. HTTP 요청, 알람 발송 및 이력 정리를 실행하지 않습니다.
     점검 성공은 IIS 파일 배포나 페이지 응답 성공을 보장하지 않습니다.
     실제 작업 스케줄러를 등록할 때는 -ValidateOnly를 제거해야 알람이 발송됩니다.
   - 인수 예시:
     -NoProfile -NonInteractive -File "D:\DeskPlusSolution\DeskPlusScheduler\InvokeEducationAlarm.ps1" -Url "http://ep.dfinc.co.kr/DeskPlusEIP/Education/Scheduler/Alarm.aspx"
   - 기존에 등록한 작업도 인수에서 -KeyFile과 그 뒤의 키 파일 경로를 제거하고 새 스크립트로 교체합니다.
   - 시작 위치: D:\DeskPlusSolution\DeskPlusScheduler (따옴표 없이 입력)
   - PowerShell 실행 정책은 서버 및 조직의 기존 정책을 따릅니다. 정책 오류가 나면 관리자에게 서명·실행 허용 여부를 확인하고
     실행 정책을 임의로 해제하지 마십시오. PowerShell 3.0 이상이 필요합니다.
   - 트리거: 매일 오전 10:00, 한국 시간대(서울 / Korea Standard Time).
     하루에 한 번 기존 알람 작업을 실행하면 됩니다. 진행상태 갱신 프로시저는 별도 스케줄로 실행합니다.
   - 서버의 Windows 시간대도 한국 시간으로 확인합니다. 서버가 다른 시간대이면 선택한 KST 실행 시각에 맞추어 트리거를 조정합니다.
   - 일반: 사용자 로그온 여부와 관계없이 실행. 스크립트를 실행할 수 있는 전용 실행 계정 사용.
   - 설정: 작업 실패 시 5분 간격으로 최대 3번 다시 시작.
   - 설정: 이미 실행 중이면 새 인스턴스를 시작하지 않음.
   - 호출 스크립트의 종료 코드 0은 성공, 1은 실패입니다.
   - 클라이언트 대기 시간은 기본 660초이며 -TimeoutSeconds로 조절할 수 있습니다.
     페이지 처리 제한은 600초입니다. 처리량이 많은 경우 운영 검토 후 함께 조정합니다.
   - IIS 유휴 종료, 서버 재시작 및 네트워크 실패에 대비하여 트리거와 실패 재시도 설정을 확인합니다.
   - -ValidateOnly 없이 실행하면 운영자의 첫 수동 실행부터 실제 알람이 발송됩니다. 운영 데이터로 테스트하지 마십시오.

5. 운영 확인
   - 성공 응답/스크립트 출력은 대상·발송·제외·실패·이력정리 건수를 표시합니다.
   - cleanedHistoryCount는 삭제한 알람 이력 수이며 알람 발송 수(sentCount)와 다릅니다.
   - historyCleanupFailed는 이력 정리 실패 여부입니다. 발송 실패가 없고 이력 정리도 성공해야 success = true입니다.
   - 알람 일부 실패 또는 이력 정리 실패는 HTTP 500입니다. 발송이 성공했더라도 정리 실패만으로 HTTP 500이 될 수 있으며,
     발송 건수와 이력 정리 실패를 구분하여 확인합니다. 스크립트는 종료 코드 1을 반환하여 기존 실패 재시도 설정을 유지합니다.
   - 스케줄러의 마지막 실행 결과가 0인지 확인하고 실패 시 DB 발송 이력 및 서버 설정을 점검합니다.
   - Teams 발송 성공 시 dbo.DP_EDU_AlarmTeamsDelivery의 SentAtUtc에 발송 확인 시각(UTC)이 기록됩니다.
     기존 dbo.DP_EDU_AlarmHistory의 Status = '1'은 이전 메신저 큐 접수 성공 이력입니다.
   - 메시지 준비 오류(PREPARE_FAILED)나 Teams 요청이 거부된 경우(MESSAGE_FAILED)는 기존 실패 이력에 기록하여 재시도합니다.
   - SentAtUtc가 비어 있고 로그에 TEAMS_PENDING 또는 TEAMS_UNCONFIRMED가 남은 건은 스케줄 작업을 중지한 상태에서 Teams 발송 여부를 확인합니다.
     발송이 확인되면 발송 시각을 기록하고, 발송되지 않은 것으로 확인되면 기존 실패 이력에 기록한 뒤 해당 발송 대기 행을 제거합니다.
   - Teams 메시지의 문서 링크는 기존 알림과 동일한 LoginOutSide.aspx 자동 로그인 경로를 사용합니다.
   - 임의 날짜/회사/사용자 값을 요청으로 받아 과거 알람을 강제 발송하는 기능은 제공하지 않습니다.
   - 완료 처리 또는 퇴직 처리된 사용자에게는 재시도 시 발송하지 않습니다.
   - 누락·장기 장애 시의 재발송 범위는 운영자가 발송 이력을 먼저 확인한 뒤 별도로 판단합니다.

6. 매일 00시 교육 진행상태 / D-Day 갱신 작업 (알람 작업과 별도)
   - InvokeEducationStatus.ps1은 sqlcmd 설치 없이 기존 사이트의 SQLConnSolution 연결 설정으로
     dbo.DP_EDU_List_UpdScheduler 저장 프로시저를 매개변수 없이 실행합니다.
   - HTTP 페이지를 호출하거나 메신저 알람을 발송하지 않습니다. 기존 오전 10시 알람 작업은 그대로 유지합니다.
   - 회사 1, 한국 시간의 기준일, 완료 상태 보존 및 D-Day 계산은 배포된 저장 프로시저의 기준을 따릅니다.
   - 운영 DB에는 dbo.DP_EDU_List_UpdScheduler 프로시저가 미리 배포되어 있어야 합니다.
     이 스크립트는 테이블 / 프로시저를 생성하거나 변경하지 않습니다.

   [파일 복사 및 DB 연결 설정]
   - InvokeEducationStatus.ps1을 웹 루트 밖의 아래 폴더로 복사합니다.
     D:\DeskPlusSolution\DeskPlusScheduler\InvokeEducationStatus.ps1
   - 기본 설정 파일은 스크립트 폴더의 상위 폴더 아래 DeskPlusEIP\WebConnectionString.config입니다.
     위 예시 경로에 복사한 경우 다음 파일을 읽습니다.
     D:\DeskPlusSolution\DeskPlusEIP\WebConnectionString.config
   - 이 경로는 운영 사이트의 실제 물리 경로가 위 구조와 같을 때만 맞습니다.
     다른 위치에 배포된 사이트는 -ConfigPath "실제 WebConnectionString.config 전체 경로"를 명시합니다.
     스크립트는 설정 파일을 임의로 검색하거나 다른 파일의 연결 정보로 대체하지 않습니다.
   - 설정 파일의 connectionStrings / add 중 name="SQLConnSolution"인 연결 정보만 사용합니다.
     DB 비밀번호를 작업 스케줄러 인수에 넣거나 출력하지 않습니다.
   - 실행 계정에는 스크립트 및 해당 설정 파일의 읽기 권한과 DB 접속 / 프로시저 실행 권한이 필요합니다.
     Windows 인증 연결은 작업 실행 계정으로 접속합니다. SQL 인증 연결은 설정 파일의 기존 접속 정보를 사용합니다.
   - 스크립트 변경 권한과 DB 연결 설정 파일 접근 권한은 NTFS 권한으로 운영 관리자 / 실행 계정에 한정합니다.

   [발송 / 상태 변경 없는 사전 점검]
   - 실제 운영 서버의 PowerShell에서 아래 명령을 실행합니다.
     & "C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -NonInteractive -File "D:\DeskPlusSolution\DeskPlusScheduler\InvokeEducationStatus.ps1" -ValidateOnly
   - 기본 설정 파일 경로와 실제 운영 파일 경로가 다르면 다음과 같이 명시합니다.
     & "C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -NonInteractive -File "D:\DeskPlusSolution\DeskPlusScheduler\InvokeEducationStatus.ps1" -ConfigPath "실제 WebConnectionString.config 전체 경로" -ValidateOnly
   - -ValidateOnly는 설정 파일 읽기, DB 연결 및 읽기 전용 메타데이터 검사만 수행합니다.
     프로시저 존재 여부, 호출 매개변수가 없는지 및 실행 권한을 점검하며 실제 갱신 프로시저는 실행하지 않습니다.
     점검 성공은 프로시저 내부 실행 및 실제 데이터 갱신 성공까지 보장하지 않습니다.
   - 점검 실패 시 운영 설정 / 권한 / 배포 상태를 먼저 확인합니다.
     점검하려고 -ValidateOnly를 제거하지 마십시오. 제거하면 실제 교육 상태와 D-Day가 갱신됩니다.

   [Windows 작업 스케줄러 등록]
   - 작업 만들기 / 이름: 교육 진행상태 및 D-Day 갱신
   - 일반: 사용자 로그온 여부에 관계없이 실행. 위 설정 파일과 DB에 접근할 수 있는 실행 계정을 선택합니다.
   - 트리거: 매일 오전 00:00:00 / 1일 간격 / 사용
     서버의 Windows 시간대는 한국 시간(서울 / Korea Standard Time)인지 확인합니다.
   - 동작: 프로그램 시작
   - 프로그램/스크립트:
     C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe
   - 인수 추가 (실제 예약 실행용, -ValidateOnly 없음):
