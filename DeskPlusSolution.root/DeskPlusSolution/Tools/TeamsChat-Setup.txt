DeskPlus Teams 1:1 채팅 연결 (.NET Framework 4.8 / VS2022)

발신 계정: 그룹웨어 / ep@dfinc.co.kr
수신자: Alarm.cs에서 회사/사용자 ID로 DB에서 조회한 이메일
전송: 발신 계정 확인 → 이메일 또는 UPN으로 Entra 사용자 조회 → 1:1 채팅 생성/재사용 → 메시지 1회 발송
채팅에 표시되는 이름은 Teams에 등록된 발신 계정의 표시 이름을 따릅니다.
Teams 앱 설치나 TeamsAppId는 사용하지 않습니다.

1. Microsoft Entra 관리 센터에서 앱을 설정합니다.
   테넌트 ID: 80bfb2b4-4d6f-4571-ab02-d07419e830f7
   애플리케이션(클라이언트) ID: 010b717d-6e77-4cbb-a5b8-f87aa943fb75

   API 사용 권한 → 권한 추가 → Microsoft Graph → 위임된 권한:
     User.Read              발신 계정 확인
     User.ReadBasic.All     DB 수신자 이메일에 해당하는 사용자 ID 조회
     Chat.Create            1:1 채팅 생성/기존 채팅 재사용
     ChatMessage.Send       로그인 계정으로 메시지 발송
     offline_access         갱신 토큰 발급
   조직 동의 정책에 맞게 관리자 동의를 허용합니다.
   인증 → 고급 설정 → 공용 클라이언트 흐름 허용: 예
   최초 연결은 장치 코드 방식으로 Microsoft 로그인 페이지에서 진행합니다.
   리디렉션 URI, 사용자 비밀번호 설정, Client Secret, TeamsActivity.Send는 사용하지 않습니다.
   기존 활동 알림 권한은 다른 용도가 없는지 확인한 뒤 관리자가 정리할 수 있습니다.

2. DeskPlusEIP\WebAppSettings.config를 확인합니다.
   TeamsChatEnabled=true
   TeamsSenderUserPrincipalName=ep@dfinc.co.kr
   TeamsChatTokenPath=%ProgramData%\DeskPlus\TeamsChat\010b717d-6e77-4cbb-a5b8-f87aa943fb75\refresh-token.dat

   토큰 경로는 전용 디렉터리를 사용하고 소스/Git/웹 사이트 밖에 두세요.
   IIS 실행 계정은 디렉터리에 수정 권한이 필요합니다(토큰 회전 및 잠금 파일).

3. 실제 IIS 서버에서 관리자 권한으로 Windows PowerShell 5.1을 실행합니다.
   솔루션 디렉터리에서 다음을 실행하세요.

   powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\Tools\Connect-TeamsChat.ps1 -IisIdentity 'IIS APPPOOL\DeskPlusEIP'

   RemoteSigned는 이 PowerShell 프로세스에만 적용되며 컴퓨터의 실행 정책을 변경하지 않습니다.

   실제 앱 풀이 다르면 해당 이름 또는 사용자 지정 실행 계정을 지정합니다.
   예: -IisIdentity 'IIS APPPOOL\실제앱풀명'
   여러 앱 풀이 같은 발신 계정을 쓰면 쉼표로 모든 실행 계정을 지정합니다.
   스크립트는 현재 로그인한 Windows 사용자에게도 권한을 주므로 VS/IIS Express에서도 사용할 수 있습니다.
   최초 연결 스크립트는 솔루션의 TeamsChatTokenStore.cs 또는 배포 패키지 Tools\Support의 지원 소스를 사용합니다.

   화면에 표시된 Microsoft 주소를 브라우저로 열고 코드를 입력한 뒤
   ep@dfinc.co.kr 계정으로 로그인합니다. 필요한 MFA도 Microsoft 로그인 화면에서 완료합니다.
   다른 계정으로 로그인하면 저장하지 않고 중단합니다.
   연결 성공 후 TeamsChatEnabled=true로 설정합니다. 이 스크립트는 테스트 채팅을 보내지 않습니다.

4. 연결 성공 후 기존 그룹웨어 업무 알림을 발생시켜 1:1 채팅 수신을 확인합니다.
   본문 전체(활동 알림의 150자 제한 없음), 제목, 문서 링크가 전송됩니다.
   같은 두 계정 사이의 기존 채팅은 재사용됩니다. 자동 발송 재시도는 하지 않습니다.
   기존 SendTeamsAppAlarm 메서드도 호환성을 위해 같은 1:1 채팅 코드로 연결됩니다.

운영:
   사용자 비밀번호는 코드/설정 파일에 저장하지 않습니다.
   갱신 토큰은 Windows DPAPI(LocalMachine)로 암호화하고 전용 디렉터리 ACL로 접근을 제한합니다.
   액세스 토큰은 메모리에만 보관하며 만료 전에 갱신합니다. 회전된 갱신 토큰은 원자적으로 저장합니다.
   비밀번호 변경, 세션 취소, 조직의 로그인 주기/조건부 액세스 등에 따라 재로그인이 필요할 수 있습니다.
   재로그인 오류가 기록되면 같은 연결 스크립트를 다시 실행하세요.
   장치 코드 로그인을 조직에서 차단한 경우 관리자와 허용되는 로그인 방식을 확인해야 합니다.
   서버를 바꾸면 기존 암호화 파일을 복사하지 말고 새 서버에서 다시 연결합니다.
   발신 계정은 Teams 사용 권한/라이선스와 해당 수신자와 채팅할 수 있는 정책이 필요합니다.
   DB 이메일은 테넌트 사용자의 mail 또는 userPrincipalName과 일치해야 합니다(별칭 proxyAddresses는 조회하지 않음).
   이 구현은 조직 내부 일반 사용자 간 채팅을 대상으로 합니다.
   메시지는 로그인 사용자가 보낸 것이므로 임의의 from/displayName으로 가장하지 않습니다.

재로그인 안내 메일
  WebAppSettings.config의 TeamsReauthNotificationEmail에서 관리자 수신 주소를 관리합니다.
  현재 원본 설정: jssong@dfinc.co.kr
  예: <add key="TeamsReauthNotificationEmail" value="admin@example.com;operator@example.com" />
  쉼표 또는 세미콜론으로 여러 주소를 지정할 수 있고, 빈 값/설정 없음은 발송하지 않습니다.
  웹과 모바일 각각의 WebAppSettings.config에 설정합니다. 템플릿 기본값은 비워 두었습니다.

  업무 알림을 Teams에 보낼 때 Microsoft가 invalid_grant, interaction_required,
  consent_required를 반환하거나 발신 계정/필수 위임 권한이 맞지 않으면 안내합니다.
  토큰 파일이 없거나 비어 있거나 복호화되지 않는 경우에도 재로그인을 안내합니다.
  토큰 파일 삭제는 캐시 사용 전에 확인하여 메모리 토큰이 남아 있어도 Teams 발송을 중단합니다.
  refresh-token.dat.lock은 동시 접근 제어용 파일이며 토큰을 대신하지 않습니다.
  네트워크 일시 오류나 일반 수신자 오류에는 재로그인 메일을 보내지 않습니다.
  정상 자동 갱신마다 메일을 보내지 않으며, 별도의 주기 검사/사전 만료 예측은 수행하지 않습니다.
  따라서 알림 발송이 없는 동안 발생한 토큰 취소는 다음 발송 시도에서 감지합니다.

  기존 그룹웨어 EML 발송 경로를 사용하므로 Teams 토큰 없이 안내 메일을 생성합니다.
  웹: /DeskPlusEIP/EmlSpool 및 기존 UseMailSendByService 설정에 따른 발송.
  모바일: /DeskPlusMobile/EmlSpool에 저장하며 기존 메일 발송 서비스가 처리해야 합니다.
  운영 서버의 메일 발송 서비스(DpEpmangr.exe 등)가 해당 경로를 처리하는지 확인하세요.
  발신 메일 주소는 TeamsSenderUserPrincipalName을 사용합니다.
  메일 생성 성공은 수신함 배달 완료를 의미하지 않습니다. 실제 배달은 운영 메일 서비스에 따릅니다.

  동일 TeamsChatTokenPath를 쓰는 웹/모바일은 24시간에 한 번만 발송 대기열에 넣습니다.
  토큰 경로 옆 .reauth-mail.sent 파일에 최근 발송 시간을 보관하여 IIS 재시작 후에도 제한합니다.
  정상 Teams 발송 또는 Connect-TeamsChat.ps1 재연결 성공 후 제한을 초기화합니다.
  메일 발송 대기열 저장 실패 시 성공 시각을 기록하지 않고 다음 업무 알림에서 다시 시도합니다.
  메일에는 토큰, Microsoft 오류 원문 또는 업무 문서 링크를 포함하지 않습니다.
